# 对话交互（Interactions）

Interactions 管理持久化的问题、可比较的选项和用户实际提交的回答。可选的 `ask_user` 工具
在问题所属的对话轮次中展示表单，并等待人工回答。它不增加执行阶段、Plan 审批、模型调用预算、
重试次数、迭代上限或用户回答超时。

用户可以选择一个选项，在问题允许时多选，补充自己的表述，或者关闭问题。
推荐选项不会自动提交。普通消息输入框仍可使用：可信的人类消息会打断表单等待，
但不会被解释为用户选择了某个选项。已完成的交互记录在刷新后仍然可读，并保留原始 Run/轮次身份。

`interactions/sessions` 是受 CAS 保护的 Storage 数据域。Host 重启会将旧的待回答请求标记为已中断，
不会重建旧工具调用。Run 中止会打断其拥有的等待；删除 Session 会移除对应记录。
浏览器状态只是读取结果的投影，不能自行确认回答或授予权限。

领域能力、工具、Plan 适配器、Session Feature 和浏览器界面贡献由独立的 Cordis Entry 管理。
`WISH_INTERACTIONS_ENABLED=0` 可停用默认装配。产品没有独立的交互页面：问题通过主对话的消息贡献
渲染，原始工具详情保留在已有的工具视图中。

默认装配只在 WebUI 入口启用此能力；无人工回答界面的 CLI 和子 Agent 配置不会暴露该工具。
Plan 和 Coordinator 适配器只接纳 Session 范围内的 `interaction.ask:` 控制操作。
浏览器草稿在页面切换后保留；`sessionStorage` 可用时，同一标签页刷新也会保留草稿。
已确认的回答保存在 Host 存储中。提交失败会保留草稿，不可用或已归档的会话不能提交过期回答。

浏览器的快速轮询跟随每次提问调用的最新生命周期状态，在完成、失败、拒绝或中止后停止。
如果问题调用已经派发但尚未生成请求记录，轮询会复用正在进行的 Session Feature 读取，
避免使该读取失效；较慢的响应仍然能够发布问题。

运行 `npm run test:interactions` 验证领域逻辑、生命周期和客户端行为；
运行 `npm run test:interactions:browser` 验证真实 WebUI 与本地确定性模型 Provider 的往返交互，
包括桌面和窄屏视口。该测试验证产品集成，不衡量外部模型 Provider 的决策质量。
